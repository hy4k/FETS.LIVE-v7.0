# Restore Add User and complete staff details

User Management again has a visible **Add User** action for super admins. The form includes name, email, masked initial password, contact number, role, branch, department, position, joining date, payslip employee ID/designation, certificates, attended training, future plans and remarks. Saved users appear in the list and are selected for follow-up editing. The Growth tab is restored for existing profiles. New inputs start empty; no previous employee's personal data is copied. Mobile profile headings/actions and tabs now wrap instead of hiding the selected name.

The deployed `create-staff-user` endpoint previously accepted unauthenticated requests, logged the submitted payload, and sent an obsolete `branch_location` column to `staff_profiles`. Version 33 authenticates the bearer token with Supabase Auth, checks active super-admin authority, maps only known profile fields and handles the existing base-centre constraint. Passwords are neither logged nor stored in staff profiles/metadata. The endpoint uses server-owned app_metadata roles for newly provisioned admins, plus the verified existing Mithun/Niyas accounts as legacy bootstrap identities; a writable profile/user_metadata role alone cannot authorize creation. Only a newly created login is rolled back if saving its profile fails; existing accounts are never overwritten or deleted on duplicate email.

Supabase project: FETS Live `qqewusetilxxfvfkmsed` only. The existing function's `verify_jwt=false` setting is retained because the handler now validates the session itself. No database migration is required. The deployed version 33 source was fetched back and matched both reviewed files exactly. Anonymous POST returns 401, OPTIONS returns 200. Before/after counts remain 17 Auth users and 12 staff profiles. No real account was created for testing.

Validation: 14 focused form/handler tests, TypeScript and production build. Isolated browser checks at 1440px and 393px cover the actual User Management button, every field, failed-save recovery, selecting the newly created fixture profile, editing growth details and ordinary-staff denial. Account creation succeeds against controlled test doubles; no production employee was created. Full lazy application module evaluation is a required deployment gate.
