# Expanded AI implementation contract

Owner has explicitly requested completion and deployment of all module coverage. Ordinary users follow User Management settings; super_admin has all application capabilities. Sensitive changes prepare human-review drafts. Existing working operations, runtime configuration and rollback artifacts must be preserved. No model-callable approval, raw SQL/table/RPC access, credential access, actor impersonation or self-permission changes.

## Database/API contracts

- `public.fets_ai_access(p_branch text)` returns `{userId,profileId,branch,admin,role,permissions,modules,operations}`. Permissions contains only relevant booleans. Validate active linked, verified/unbanned/undeleted Auth account. Canonical super-admin identity follows the server-protected User Management role, not user metadata or client fields. Ordinary centre access must be verified. Inspect/harden the existing protected-profile trigger boundary so a caller cannot promote their own role or edit their permission grants. Preserve non-security profile edits and existing protected workflow side effects.
- `public.fets_ai_operation(p_operation text,p_values jsonb,p_branch text,p_request_id uuid)` returns existing `{type:'action-result',tool,status:'succeeded'|'blocked'|'failed',recordId?,path?,title?,message?,record?}` for ordinary execution or a `ChangeReview` below. Closed, named operation definitions only. Every write rechecks User Management permission, ownership/centre, controls, exact allowed fields, versions and replay. Domain rules/side effects are authoritative; no generic fallback. Use review/module handoff for complex actions whose final execution belongs to an existing dedicated workflow.
- `public.fets_ai_review(p_id uuid,p_decision text)` is authenticated human UI only, **never an AI tool**. Decisions apply/cancel. Accept no replacement arguments. Bind to stored actor/operation/centre/payload/version/expiry; recheck current permissions/OFF; no blind retry after changed target. Cancel is non-business-mutating. Actions that require provider credentials/physical attestation/complex existing workflow return `applyMode:'module'` and an honest module handoff, never fabricated completion.
- Table `public.fets_ai_reviews`: server-write-only review storage, safe client SELECT under ownership/role checks. Fields public projection: `id,operation,label,module,path,branch,status,apply_mode,record_id,before_values,proposed_values,summary,expires_at,created_at,decided_at,result`. API maps to ChangeReview.
- `ChangeReview` result: `{type:'change-review',id,operation,label,module,path,branch,status:'pending'|'applied'|'cancelled'|'expired'|'stale'|'blocked',applyMode:'database'|'module',recordId?,before:Record<string,unknown>,proposed:Record<string,unknown>,summary:string,expiresAt:string,createdAt?:string,result?:ActionResult}`. A preview is never a succeeded business action.
- Management API actions: `reviews` -> `{reviews:ChangeReview[]}`; `review` with `reviewId` -> `{review:ChangeReview}`; `review-decide` with `reviewId,decision:'apply'|'cancel'` -> `{review:ChangeReview}`. Human UI calls these, not model functions.

Database implementer owns `supabase/functions/fets-ai-agent/operation-definitions.ts`: exported `OPERATION_DEFINITIONS`, an array of `{name,label,module,path,permission,review,applyMode,scope,parameters}`. `scope` is centre/shared/own. `parameters` is Gemini-compatible JSON schema. Exact named operations cover calendar/catalogue, cases/tasks, roster, Shift/daily reports, attendance, applications/swaps/OT/payroll, institutions/stages/duties/results, systems/assets/lost-found, news/business, team conversations, personal desk/documents, staff/delegation, knowledge/settings and Access Hub metadata/handoffs. Preserve factual limitations: external publishing/account creation/secret entry/physical signatures require existing workflow handoff when appropriate. No password/token/secret fields in schemas or projections.

Root integrates operation definitions into tool declarations, scope/intent and current sources. Database authority and TS registry must have the same closed names and fields. A missing or unverified operation is unavailable, never silently routed to generic writes.
